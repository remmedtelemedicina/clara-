Por que aconteceu
1
Esse número de telefone já tinha uma conversa anterior
O paciente conversou com a Clara antes. Ao final daquela conversa, o campo setor no Supabase foi atualizado para "ENCERRADO".
2
Na nova conversa, o N8N leu o setor do banco — e ainda era ENCERRADO
O workflow fez o Get a row no Supabase, leu setor = "ENCERRADO" e passou esse valor para a Clara.
⚠️ O N8N não sabe distinguir "conversa antiga encerrada" de "conversa nova". Ele só lê o setor e passa para frente.
3
O ALERTA 0 do prompt disparou corretamente — mas no contexto errado
A Clara leu setor = "ENCERRADO" e executou o ALERTA 0 como foi programada para fazer. O prompt está certo. O problema é que o setor não devia ser ENCERRADO.
ALERTA 0: Se setor = "ENCERRADO" → output: "Nossa conversa foi encerrada." ✅ correto

Antes vs. depois da correção

❌ Antes — comportamento errado

1.Paciente envia nova mensagem
2.N8N lê setor = ENCERRADO (de conversa antiga)
3.Clara dispara ALERTA 0 imediatamente
4.Paciente recebe "Nossa conversa foi encerrada" 😞

✅ Depois — comportamento correto

1.Paciente envia nova mensagem
2.N8N lê setor = ENCERRADO + verifica tempo
3.Detecta que passou mais de 4h → reseta para TRIAGEM_ATIVA
4.Clara atende normalmente 🧡
Passo a passo — implementar no N8N
⚠️ Fazer isso antes do agente Clara no workflow — não dentro do prompt.

Como adicionar o nó de verificação

1
Adicionar campo updated_at no Supabase
A tabela de clientes/conversas precisa ter um campo com a data/hora do último contato para calcular o tempo decorrido.
ALTER TABLE clientes ADD COLUMN IF NOT EXISTS ultimo_contato timestamptz DEFAULT NOW();

-- Atualizar esse campo a cada mensagem recebida
2
Adicionar nó IF após o "Get a row"
No N8N, arraste um nó IF entre o "Get a row" e o agente Clara. Configure a condição:
-- Condição do nó IF: {{ $json.setor }} == "ENCERRADO" AND {{ $now.diff($json.ultimo_contato, 'hours') }} > 4
3
Branch TRUE — Supabase UPDATE + resetar setor
Quando a condição for verdadeira (conversa antiga encerrada + mais de 4h), adicionar um nó Supabase para resetar o setor.
-- Supabase node: UPDATE Table: clientes Update: setor = "TRIAGEM_ATIVA" Where: telefone = {{ $json.telefone }}
4
Reconectar ambos os branches ao agente Clara
Tanto o branch TRUE (após o UPDATE) quanto o branch FALSE devem conectar ao agente Clara. O agente vai receber o setor correto em ambos os casos.
5
Atualizar ultimo_contato a cada mensagem recebida
Garantir que a cada mensagem do paciente, o campo ultimo_contato seja atualizado. Isso pode ser feito no início do workflow, logo após identificar o número do paciente.
-- Supabase UPDATE no início do workflow: UPDATE clientes SET ultimo_contato = NOW() WHERE telefone = {{ $json.telefone }}
