🟠 Bugs encontrados no workflow atual
🔄
Reativação da IA depende de texto exato "Atendimento finalizado"
Quando um humano atende um paciente e termina, o workflow só reativa a Clara se alguém enviar a mensagem exata "Atendimento finalizado". Se não enviar, a IA fica pausada para aquele paciente para sempre — ele nunca mais é atendido automaticamente.
Fix: Adicionar timer automático de 30 min. Se nenhuma mensagem humana em 30 min com setor=HUMANO → reativar automaticamente.
Pacientes ficam presos sem atendimento
🗄️
Colunas de data são TEXT — impossibilita cálculo de tempo
Os campos atualizado_em e updated_at existentes na tabela estão salvos como TEXT (string), não como TIMESTAMPTZ. Isso impede qualquer cálculo de "passou X horas desde Y". A coluna ultimo_contato nova precisa ser criada como TIMESTAMPTZ desde o início.
Bloqueia implementação do reset de 4h
📝
Mensagens com aspas ou quebra de linha podem corromper o Redis
O código que salva mensagens no Redis remove aspas simples e duplas (.replace(/['"]/g, '')) mas não trata outros caracteres especiais. Mensagens com quebras de linha complexas, emojis fora do Unicode padrão ou caracteres de controle podem corromper o JSON no Redis — e a mensagem é perdida silenciosamente.
Mensagens podem ser perdidas
🗑️
/reset deleta TUDO sem backup — 4 tabelas apagadas
O comando /reset deleta dados de 4 tabelas ao mesmo tempo: dados_cliente, chats, chat_messages e n8n_chat_histories. Não há confirmação, não há backup, não há undo. Se executado por engano, histórico completo do paciente é perdido.
Fix sugerido: /reset deve apenas limpar a memória Redis e resetar o setor — nunca deletar o histórico.
Dados permanentemente perdidos se usado errado
🌍
Pacientes internacionais ficam com setor=HUMANO para sempre
Quando um número internacional (não começa com 55) manda mensagem, o workflow seta setor = "HUMANO" e para. Se esse mesmo número mandar mensagem novamente, cai em um loop — setor é HUMANO, IA não atende, humano não foi notificado novamente.
Caso raro mas sem tratamento

Transcrição de áudio via OpenAI, análise de imagem via GPT-4o-mini, OCR de documentos via Gemini — todos funcionando.

Clara, Triagem Médica, Agenda Consulta, Renovação de Receita e Escalar Humano — todos conectados e com memória em Postgres.

Buffer de 10 segundos para múltiplas mensagens
Paciente que manda várias mensagens seguidas tem todas agrupadas antes de chegar na Clara — evita respostas parciais.
⏸️
Pausa para atendimento humano
Quando humano assume, o campo atendimento_ia é setado para "pause" e Clara para de responder. Funciona, mas precisa da melhoria do timer de 30min.
📱
Filtro de mensagens próprias
Mensagens "outcoming" (enviadas pelo próprio número) são filtradas — a Clara não processa as próprias respostas como se fossem do paciente.
