Por que aconteceu — causas do Bug A
1
O modelo executou 3 etapas em 1 turno
O prompt tem a regra "execute APENAS a etapa correspondente e encerre". Mas ao receber "Sim", o modelo decidiu ser "eficiente" e executou: confirmação → pergunta de leveza → identificação de grupo → exibição de checklist — tudo de uma vez.
# Regra violada no prompt: "Execute APENAS a etapa correspondente — nunca execute mais de uma etapa por turno" # O modelo ignorou essa regra
2
O checklist mostrado não existe no prompt — foi inventado
A Clara não usou nenhum dos 18 grupos de sintoma. Criou uma lista genérica misturada. Isso acontece porque ela mostrou o checklist antes de saber o sintoma — sem saber o grupo, inventou uma lista "universal" que não está no prompt.
# Regra violada: "Copiar texto EXATO dos grupos de sintoma — não resumir, não adaptar, não inventar" # Clara criou lista própria porque não tinha grupo identificado
3
Possível: setor estava em estado avançado de conversa anterior
Se o banco Supabase tinha setor = "TRIAGEM_ALARME" de uma conversa anterior, a Clara leu esse estado e foi direto ao checklist sem passar pelas etapas anteriores. Isso conecta Bug A com Bug B.
# Cenário combinado: Supabase: setor = "TRIAGEM_ALARME" (de ontem) Nova mensagem: "Sim" Clara lê setor → pula para MOMENTO 1 → mostra checklist # Paciente nunca disse sintoma nessa conversa

🟠 Bug B — Setor ENCERRADO na conversa nova

Paciente abre nova conversa e Clara responde "Nossa conversa foi encerrada" sem motivo aparente.

Por que isso acontece

O WhatsApp não tem "sessão" — o N8N não sabe que é uma conversa nova

💡
Para o N8N, cada mensagem que chega é apenas um webhook com { telefone, mensagem }. Ele identifica o paciente pelo número de telefone e busca os dados no Supabase — sem saber se é continuação de conversa ou início de uma nova.
1
Paciente envia nova mensagem (nova conversa)
Ex: mandou "Olá" ou "2" para iniciar novo atendimento
2
N8N recebe webhook → identifica pelo telefone → busca no Supabase
Encontra: setor = "ENCERRADO" (gravado da conversa de ontem/semana passada)
3
N8N passa setor = "ENCERRADO" para a Clara
O N8N não verifica há quantas horas está assim — simplesmente lê e repassa
4
Clara executa ALERTA 0 → "Nossa conversa foi encerrada" ❌
O prompt está certo — o problema é o setor incorreto que veio do banco
O que o N8N precisa verificar (novo nó IF)

Fluxo correto após a correção

Como os dois bugs se combinam — o cenário mais perigoso

D-1

Supabase gravou: setor = "TRIAGEM_ALARME"
D

N8N lê setor = "TRIAGEM_ALARME" do banco
!
Clara recebe setor = "TRIAGEM_ALARME" e vai direto ao checklist

❌

⚠️
Por isso o reset de setor no N8N (correção do Bug B) também resolve parte do Bug A. As duas correções precisam ser feitas juntas.
Todas as correções necessárias

5 correções — Prompt (Clara) + N8N

1
📝 Prompt Clara
ETAPA 3 — Adicionar instrução de parada obrigatória
Após o paciente confirmar "Sim" (confirmação da consulta), a Clara deve perguntar leveza e encerrar o turno imediatamente — sem avançar para checklist nem pedir sintoma.
# Localizar no prompt: seção ETAPA 3 / TRIAGEM_SINTOMA # Adicionar ao final do bloco "SIM:" 🔴 ENCERRAR IMEDIATAMENTE APÓS ESTE OUTPUT. 🔴 NÃO continuar para próxima etapa. 🔴 NÃO mostrar lista de alarme. 🔴 NÃO pedir sintoma agora — aguardar próximo turno.
2
📝 Prompt Clara
ETAPA 3A — Adicionar instrução de parada obrigatória
Após pedir o sintoma principal ao paciente, a Clara deve encerrar o turno — sem identificar grupo nem mostrar checklist antes de receber a resposta.
# Localizar no prompt: seção ETAPA 3A / TRIAGEM_LEVEZA # Adicionar ao final do bloco "SIM:" 🔴 ENCERRAR IMEDIATAMENTE APÓS ESTE OUTPUT. 🔴 NÃO identificar grupo de sintoma agora. 🔴 NÃO mostrar checklist agora. 🔴 Aguardar o sintoma no próximo turno.
3
📝 Prompt Clara
ETAPA 3B MOMENTO 1 — Verificar se sintoma foi informado antes de mostrar checklist
No início do MOMENTO 1, verificar se a mensagem contém um sintoma real. Se for só "Sim", "Ok" ou vaga — pedir o sintoma antes de qualquer coisa.
# Localizar no prompt: seção ETAPA 3B / MOMENTO 1 # Adicionar NO INÍCIO, antes de qualquer outra instrução: 🔴 ANTES DE QUALQUER COISA: verificar se paciente informou sintoma. Se a mensagem for apenas "Sim", "Ok", "Pode" ou vaga E não há sintoma na memória da conversa → NÃO mostrar checklist. NÃO atualizar setor. Output obrigatório nesse caso: "Para eu conseguir te atender, preciso saber: qual é o seu *principal sintoma* agora? (Ex: dor de cabeça, gripe, dor nas costas...)" 🔴 Aguardar resposta. Encerrar turno.
4
⚙️ N8N
Adicionar coluna ultimo_contato no Supabase + nó IF no workflow
A tabela de pacientes precisa de um campo com data/hora do último contato. O N8N verifica esse campo antes de passar o setor para a Clara.
-- Passo 1: adicionar coluna no Supabase ALTER TABLE clientes ADD COLUMN IF NOT EXISTS ultimo_contato timestamptz DEFAULT NOW(); -- Passo 2: nó IF no N8N (entre "Get a row" e agente Clara) Condição: {{ $json.setor }} == "ENCERRADO" AND {{ $now.diff($json.ultimo_contato, 'hours') }} > 4 Branch TRUE → Supabase UPDATE setor = "TRIAGEM_ATIVA" Branch FALSE → segue sem alteração
5
⚙️ N8N
Atualizar ultimo_contato a cada mensagem recebida
No início do workflow, assim que o número do paciente é identificado, atualizar o campo ultimo_contato. Isso garante que o cálculo de tempo seja sempre preciso.
-- Supabase UPDATE no início do workflow (antes do IF): UPDATE clientes SET ultimo_contato = NOW() WHERE telefone = {{ $json.telefone }}

2 ETAPA 3A — instrução de parada (🔴 ENCERRAR) Prompt da Clara (n8n) 🔴 Urgente
3 ETAPA 3B MOMENTO 1 — checar sintoma antes do checklist Prompt da Clara (n8n) 🔴 Urgente
4 Coluna ultimo_contato + nó IF (reset setor após 4h) Supabase + N8N workflow 🟠 Alta

✅
Depois dessas 5 correções: Clara só mostrará o checklist de alarme após receber o sintoma do paciente. Conversas novas sempre iniciarão com setor correto. Pacientes não serão mais bloqueados sem motivo.
