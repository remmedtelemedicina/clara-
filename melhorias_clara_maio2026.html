O que aconteceu: em algumas conversas, Clara negou o atendimento (mandou para UPA, recusou por urgência) ou o paciente encerrou. Mesmo assim, o follow-up automático disparou depois perguntando se a pessoa precisava de consulta — situação constrangedora e fora de contexto.
❌ Clara mandou o paciente para UPA/SAMU (bloqueio de segurança)
❌ Atendimento foi recusado por urgência ou situação inadequada
❌ Paciente encerrou voluntariamente ("obrigado, resolvi em outro lugar")
❌ Equipe humana assumiu a conversa
❌ Pagamento já foi confirmado

✅ Follow-up DEVE disparar apenas quando:
→ Paciente abandonou no meio do pagamento
→ Paciente começou o cadastro mas não finalizou
→ Paciente iniciou triagem mas parou de responder
CONTROLE DE FOLLOW-UP: Ao encerrar qualquer atendimento, defina internamente o motivo_encerramento conforme abaixo. O sistema de follow-up usa esse valor para decidir se dispara ou não. Valores possíveis: - "pagamento_pendente" → follow-up DEVE disparar - "cadastro_incompleto" → follow-up DEVE disparar - "abandonou_triagem" → follow-up DEVE disparar - "bloqueado_alarme" → NÃO disparar (foi para UPA) - "atendimento_recusado" → NÃO disparar - "encerrado_paciente" → NÃO disparar - "pagamento_confirmado" → NÃO disparar - "equipe_assumiu" → NÃO disparar

N1 — IA continua respondendo após handoff confirmado para humano
O que aconteceu: paciente pediu "Falar com atendente". Clara confirmou a transferência. Mas quando o paciente enviou a próxima mensagem, a IA voltou a responder normalmente — como se o handoff não tivesse acontecido. A conversa ficou presa entre IA e humano ao mesmo tempo.
Paciente: "Falar com atendente"
Clara: "Você será encaminhado para um atendente humano agora ✅"
Paciente: "Sim" (confirmou)
Clara: "Você já está falando comigo, que sou a atendente virtual..." ❌
→ IA não parou de responder após o handoff
1. Quando Clara confirma o handoff para humano: → Setar variável: setor = "AGUARDANDO_HUMANO" 2. No início do nó principal da IA, adicionar condição: SE setor = "AGUARDANDO_HUMANO" → NÃO processar a mensagem com o agente IA → Pode retornar apenas: "Aguarde, um atendente já foi acionado 🧡" → OU simplesmente não responder (silêncio) 3. Quando o humano liberar a conversa de volta para a IA: → Setar setor = "MENU" (ou o estado inicial) → Pode ser feito com um comando interno tipo /liberar no painel Objetivo: a IA só processa mensagens se o setor NÃO for "AGUARDANDO_HUMANO".
Adicionar condição no nó principal de entrada da IA

N2 — Mensagens duplicadas: paciente envia 2 msgs rápidas → Clara responde 2 vezes
O que acontece: quando o paciente envia duas mensagens em sequência rápida (ex: "Oi" + "queria saber sobre consulta"), a Evolution API dispara dois webhooks separados para o n8n. O n8n processa cada um de forma independente e a IA responde duas vezes — duas mensagens da Clara chegam ao paciente quase ao mesmo tempo. Acontece também quando o paciente clica no link do site e envia uma mensagem junto com o texto automático do botão.
① Paciente: "Oi" [envia] + "tudo bem, queria saber sobre consulta" [envia logo depois]
→ Clara responde duas vezes (uma para cada mensagem)

② Paciente clica no botão do site → WhatsApp abre com texto automático
→ Chega duas mensagens quase simultâneas → duas respostas

③ Paciente pede equipe + manda outra mensagem logo em seguida
→ Duas respostas da Clara ao mesmo tempo
Opção A — Debounce simples (recomendada): Antes do nó principal da IA, adicionar um nó de "Wait" ou verificação de tempo: 1. Quando chega uma mensagem, registrar o timestamp no Supabase (ou variável de contexto) como "ultima_mensagem_recebida" 2. Aguardar 2-3 segundos antes de processar 3. Antes de chamar o agente IA, verificar: SE chegou outra mensagem do mesmo número nos últimos 3 seg: → Ignorar a mensagem anterior (processar só a mais recente) → OU concatenar as mensagens e processar uma vez só Opção B — Flag de processamento: 1. Ao receber mensagem, setar: processando = true 2. Se chegar nova mensagem enquanto processando = true: → Guardar na fila, processar após a primeira terminar 3. Ao finalizar resposta: processando = false, processar fila Opção C — Janela de agregação (mais sofisticada): Aguardar até 3 segundos após a primeira mensagem. Se chegarem mais mensagens nesse período, juntar tudo numa string e processar uma única vez com o contexto completo.
Implementar debounce antes do nó da IA no webhook de entrada
