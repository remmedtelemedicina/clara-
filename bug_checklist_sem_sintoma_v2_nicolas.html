Os Dois Cenários em que isso acontece

🔴 Cenário A — Paciente novo (ou após /reset)

Quando um paciente inicia uma conversa e o setor no Supabase já está como TRIAGEM_ALARME (de uma conversa anterior), Clara pula as etapas de confirmação e de leveza e vai direto para mostrar o checklist de alarme. O "Sim" do paciente (confirmando que quer continuar) é interpretado como se fosse uma resposta dentro da etapa de alarme.

🟡 Cenário B — Após /reset

O comando /reset limpa apenas a memória do Redis (buffer de mensagens). Ele não limpa o setor no Supabase nem a memória longa do Postgres. Então o setor continua como TRIAGEM_ALARME e a memória do Postgres ainda tem conteúdo de conversas anteriores (incluindo exemplos de sintomas que a própria Clara escreveu em mensagens antigas, como "falta de ar, dor no peito"). Clara lê esses exemplos como se fossem sintomas reais do paciente e mostra o checklist correspondente.

Causa Raiz Técnica — O que acontece por dentro

Fluxo atual (quebrado)

1

N8N busca o setor no Supabase

Retorna TRIAGEM_ALARME — valor salvo da conversa anterior. O /reset não limpou.

2

"Oi", "1", "Sim" são processados

"Oi" e "1" são roteados pelo switch do N8N (não passam pela Clara). O setor nunca é atualizado.

3

Paciente diz "Sim" — Clara recebe com setor = TRIAGEM_ALARME

Clara deveria estar na ETAPA 3 (TRIAGEM_SINTOMA) ou ETAPA 3A (TRIAGEM_LEVEZA). Mas está na ETAPA 3B porque o setor está errado.

4

Guard-rail não dispara — memória tem conteúdo antigo

O guard-rail devia pedir o sintoma. Mas ele verifica se "há sintoma na memória" — o Postgres tem conteúdo antigo da conversa anterior (incluindo exemplos de sintomas que a própria Clara escreveu). Então o guard-rail entende que "já tem sintoma" e não dispara.

5

Clara identifica grupo pelo conteúdo da memória

Com base no conteúdo antigo do Postgres (ex: mensagem anterior da Clara citando "falta de ar" como exemplo), ela identifica Grupo 1 (Respiratório) e exibe o checklist — sem que o paciente tenha dito uma única palavra sobre seus sintomas.

O que o /reset precisa fazer (vs. o que faz hoje)
Ação Hoje O que deveria fazer
Limpar Redis (buffer 10s) ✅ Faz ✅ Correto
Limpar Postgres Chat Memory ❌ Não faz ✅ Deve limpar — senão memória antiga contamina nova conversa
Resetar setor no Supabase ❌ Não faz ✅ Deve setar TRIAGEM_ATIVA — senão Clara começa no meio do fluxo
O que Nicolas precisa corrigir no N8N

1 Correção do /reset — adicionar UPDATE no Supabase + limpar Postgres

No nó do /reset no N8N, após limpar o Redis, adicionar dois passos:

-- Passo 1: Resetar setor no Supabase UPDATE dados_cliente SET setor = 'TRIAGEM_ATIVA', atualizado_em = NOW() WHERE telefone = '{{ $json.telefone }}'; -- Passo 2: Limpar Postgres Chat Memory DELETE FROM n8n_chat_histories WHERE session_id = '{{ $json.telefone }}';

⚠️ Atenção

Verificar se a tabela do Postgres Chat Memory se chama n8n_chat_histories ou outro nome no seu workflow. O session_id provavelmente é o telefone do paciente.

2 IF node para resetar setor em novas conversas (paciente sem /reset)

Para pacientes que voltam depois de horas sem ter feito /reset, adicionar um IF node no início do fluxo:

// IF node — colocar ANTES de passar para a Clara // Condição A: setor == "ENCERRADO" // Condição B: horas desde ultimo_contato >= 4 Condição: {{ $json.setor }} === "ENCERRADO" OU {{ $now.diff($json.ultimo_contato, 'hours') }} >= 4 // Branch TRUE → UPDATE setor = 'TRIAGEM_ATIVA' // Branch FALSE → continuar normalmente

📋 SQL para adicionar coluna necessária

ALTER TABLE dados_cliente ADD COLUMN IF NOT EXISTS ultimo_contato TIMESTAMPTZ DEFAULT NOW(); -- Atualizar o ultimo_contato a cada mensagem recebida UPDATE dados_cliente SET ultimo_contato = NOW() WHERE telefone = '{{ $json.telefone }}';

3 Correção do prompt (já aplicada parcialmente)

Além do N8N, o guard-rail no prompt precisa ser ajustado para não depender da memória:

❌ Condição atual do guard-rail (problemática)

SE mensagem for confirmação curta E NÃO houver sintoma no histórico → pedir sintoma

O problema: o Postgres tem conteúdo antigo → "há sintoma no histórico" = VERDADEIRO → guard-rail não dispara

✅ Condição corrigida

SE mensagem for confirmação curta independente do que está na memória → pedir sintoma
